# Study report renderer

`src/standalone/studyReport/viewModel.ts` owns current strict `lca.study-report-view.v3` and renderer `3.0.0`. The exact original renderer2 artifact at `vendor/study-renderer/v2` retains view2 and view1 historical preview/export behavior; versions are selected explicitly, never relabeled. This view protocol owns presentation only. Edge W09 owns authorized projections and detached export receipts; Worker owns numerical facts; CLI owns independently trusted verification and installed delivery. P1 request shapes and this fixture implementation do not enable report export.

## Input and numerical limits

Every field is required; extra keys fail. Current view3 requires the Edge-owned immutable `lca.study-method-report-summary.v1` contract and exact contained validator. The summary/domain wire schema is not independently recreated in Platform. All 20 requirement machine/check/professional states, 25 primary/decomposition category roles and 58 supplied catalog facts render in mandatory chapters independent of authored sections, selected claims or the author table limit. Configuration, module/source/baseline identities, frozen evidence, normalisation/weighting availability, exact units/scaling and all three false qualification flags remain explicit. Complete selected-factor records are not embedded: their exact authorized facts reference and record count are disclosed. Null, empty lists, gaps and pending professional evidence remain distinct; browser code performs no domain calculation or approval.

View3 method provenance is the strict variant `{type:"methodAssessmentFacts",id,contentHash,sourceFactId}`. The source fact ID is the exact Worker catalog ID; a separate author fact alias may differ. The contained owner validator checks selected value/unit/method/coverage/reasons against that catalog as identity validation. Retained runResult/analysisFacts provenance has only its original three fields; an extra sourceFactId fails. The exact contained component source is `f1a36ceee7d6efb9499e0edecfdd5278c27ab8e2`, producer manifest SHA-256 `c0c9e1de03016ad8a17538fd6c021be2a2a0bfdf3e08beb570009bf3cb55b24b`; its nine original files and manifest are retained under methodProtocol names, including the read-only public module metadata projection. That owner validator binds the pinned category roster/roles/units and source N/F parameters, rejects self-consistent category/N/F substitution and ineligible available-N/W states, and never recomputes characterised, normalised, weighted or candidate-score values.

The view carries exact report, Study, Run, method and fact provenance; plain text; supplied table/chart selections; sources, assumptions, cutoffs, limitations and historical validity/review state. `methodRef:null` is valid for non-LCIA facts, including supplied inventory/activity quantities and parameter assignments, with their supplied unit. Evidence says only "No LCIA method" and never infers a fact kind. The producer supplies exact parameter/evaluation/statistic labels, algorithm/settings evidence, undefined reasons and limitations in the existing typed text fields. `runs` contains actual Run provenance; an analysis-local evaluation identity belongs in its supplied context, never an invented Run. A method reference identifies category provenance; a relative delta can retain that reference with dimensionless unit `1`. Worker and the Edge claim verifier own quantity semantics. A chart requires one method identity (including null) and one unit, but its selection does not establish scientific comparability. No ranking, delta, aggregation, conversion, solver or authorization decision is computed here.

The view is bounded to 2,000,000 UTF-8 bytes, one exact baseline Run, up to32 methods/sections/tables/charts, 256 author-selected facts plus the mandatory 58-fact method catalog, 256 citations, 256 cutoffs, 128 assumptions and 64 chart facts. Generic text bounds count Unicode code points and reject unpaired surrogates, matching the exact view3 JSON schema; the whole-view bound remains UTF-8 bytes. See the executable validator for individual text/reference bounds. Text is escaped data: angle brackets and URL-like strings are preserved as literal text, without creating elements, executable code or navigable URLs. Control characters and byte/field bounds still fail; unknown fields remain rejected. Accepted long tokens wrap inside the page, grid and chart tracks; tables scroll inside their bounded region.

`canonicalValue` is a string or null. Numeric strings are at most 64 characters, with the canonical decimal/exponent spelling agreed with the Worker facts producer: zero is `0`, no plus/leading zeros/trailing fractional zeros, lowercase `e`, nonzero exponent with absolute value at most 324. This is a spelling check, not numerical recomputation or another content hash protocol. The exact string is displayed without a Number round-trip. View.v2 and view3 separate numeric availability from characterization coverage: null is displayed as "No numeric value" and may retain complete, partial or unknown coverage; a numeric value with unknown coverage still fails. Every view2/view3 fact requires `reasonCodes:string[]` (empty when no reason), bounded to32 nonempty strings of at most128 characters under the existing text/control rules. Exact supplied codes are visibly displayed separately from coverage, without interpreting, translating, deriving or recomputing them. The producer/claim verifier owns their fidelity. Retained view.v1 still requires null if and only if coverage is unknown and its preview shows "Unknown". Partial values are labeled characterized subtotals. A Number conversion is used only for SVG geometry; nonfinite, underflowed or subpixel values show explicit not-plottable text while preserving the original supplied value.

Timestamp validation checks the declared local calendar/time and numeric offset independently, preserving the original fractional precision and offset string. It does not compare an offset-local wall clock with UTC or reserialize signed input.

## Rendering and trust

`renderReport(view, context): Promise<string>` uses portable Web standards only, including Web Crypto for fixed CSP resource hashes. It reads no clock, random source, filesystem, environment, credentials or network. All dates are supplied. `renderReportBody` retains export framing and requires a real RenderContext. The internal `content.ts` module shares only validated semantic content/table/chart/escaping presentation with Platform’s separate online preview; it is not a new public renderer API. The preview has no export identity, receipt or exporter-verification claim. Renderer3.0.0 is a separate artifact and versioned export identity. Independently pinned renderer1.0.0 and the original renderer2.0.0 source44da/archive dfbc artifacts and frozen bytes remain unchanged. The current validator and both export entrypoints require view3/renderer3. Online view1/view2 preview uses the separately retained exact renderer2 package, while view3 uses validated current content; the online-only about:srcdoc fragment binding preserves same-document chapter navigation. No version fallback or projection relabeling is permitted. Controls only filter/reorder already supplied facts and expand evidence. Any facts absent from the supplied tables appear in an implicit additional-facts table, derived only from the already approved view projection. This does not mutate the 32-entry user table array or add numerical claims. Supplied and implicit table DOM IDs use disjoint namespaces.

W10's renderer copy is English. Its document `lang` and `dir` come from the shared typed locale registry's English entry, generated into the portable `documentLanguage.ts` module by `pnpm study-report:language:write`. The package build rejects stale generated metadata. Host/browser language never changes this fixed-copy renderer's document language, and the standalone artifact imports no application locale runtime. Additional report languages require a separately reviewed view/copy contract.

RenderContext is separate from hashed projection bytes: exact `exportId`, `projectionHash`, and historical `verificationAtGeneration`. It contains no report HTML hash or recursive resource aggregate. Historical exporter verification text never authenticates the file or grants current access. No public key, signature or embedded trust flag is accepted. Every file explains that its detached receipt must be checked by an independently trusted CLI/official viewer, that later withdrawals are unavailable offline, and that downloads cannot be recalled. W09 must render the same exact artifact and sign a detached manifest covering actual `report.html`, `projection.json` and fixed renderer resources. CLI verifies those exact bytes or reproduces and compares them; authenticating only hidden projection bytes is insufficient.

Native print is a derived reading copy, not a detached-receipt-verified export format. It always includes every supplied table fact, all58 method catalog records and the complete requirement/category/fact/run evidence. Each native disclosure has the same escaped evidence statically present outside `details`, hidden on screen and expanded in print; CSS does not rely on forcing closed native details open. Print uses full-width labeled records so nested evidence does not remain trapped in narrow columns. Screen filters never omit printed rows. Filter values, row order/hidden attributes and disclosure states are not mutated; the current row order is retained when printing. No print-event JavaScript is required. With JavaScript disabled, the copy identifies itself as read-only and hides filter/order controls; native disclosures and complete printing remain available.

HTML is self-contained, with no automatic requests, remote fonts/images, scripts, service workers, dynamic imports, shell bridge or persistent actions. CSP allows only the exact inline stylesheet/runtime hashes. Citations display typed identity, version and permitted digest, never raw source payload or a downloadable locator.

## Artifact and release

`pnpm study-report:build` emits the current `study-report-renderer-3.0.0.tgz` and `dist-study-report/package`, an independent dependency-free ESM/types/static-resource package, its file size/SHA-256 manifest, deterministic ustar/gzip archive and detached archive digest receipt. Manifest files exclude the manifest itself; the detached archive receipt binds it. Source commit, dirty state and source digest are explicit. `--release` rejects a dirty checkout. A checksum/local build alone does not establish release provenance.

The canonical Build/release workflow builds from its exact qualified source and preserves the archive/manifest as a bounded Actions artifact. It neither npm publishes this private application nor attaches a public release asset. Public distribution still requires an owner-approved immutable release attachment and CLI pinning of independently obtained source/archive/manifest identities. CLI bundles those qualified bytes, without sibling source imports or runtime code download. Real W09/installed-CLI acceptance remains required; fixture package proof must never be reported as completed P2 delivery.

The dedicated `study-report.yml` PR workflow qualifies relevant renderer, package, fixture, locale-registry and dependency inputs for Dev/Main. It checks out the exact PR head with read-only permissions, installs the existing frozen dependency graph, builds in clean release mode, runs focused protocol/workflow and independent-package tests, and executes the packed-HTML Chromium suite. Before upload, it verifies actual archive/manifest bytes and binds the browser proof to the same clean source, source digest and artifact hashes. The seven-day artifact contains only that package/manifest/receipt and synthetic browser proof. This workflow grants no deployment, publication or production-operation authority and leaves the existing full pre-push and release gates intact.
